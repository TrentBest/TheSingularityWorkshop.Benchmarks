## Derived throughput and scaling observations

- The 1,000-root independent composition case corresponds to approximately **1,518 complete composition operations/second** (1 / 658.671 μs). This is throughput of the benchmarked whole workload, not roots/second.
- Catalog ID lookup remained approximately 4.4–4.5 ns across catalog sizes 1 to 1,000, with 0 B/op in the reported allocation column.
- Prepared-manifest construction remained approximately 7–8 ns across 1 to 1,000 prepared roots, at 64 B/op. This benchmark isolates construction from preparing the roots.
- RuntimeAssembly lookup by ID grew from 30.2 ns at one entry to 4.14 μs at 1,000 entries. The host dictionary lookup measured 4.31 ns at 1,000 entries; the linear scan measured 1.79 μs. These are useful comparison signals, **not yet proven equivalent semantic paths**. Inspect the implementation and benchmark boundaries before treating them as an optimization target.
- Independent-root composition allocated 15.23 KB for one root and 7,343.91 KB for 1,000 roots. Composition is allocation-heavy at scale and should be profiled by phase before attempting changes.
- The 10,000-bundle deep-chain result had high uncertainty: reported error 15.067 ms against a 16.912 ms mean. Treat it as a scale/stress observation, not a stable latency claim.

## Interpretation and limitations

1. This is a three-iteration ShortRun on a virtualized CI machine. It is useful for finding scale trends and potential bottlenecks, not for declaring precise performance or setting regression thresholds.
2. The CSV exports contain mean, standard deviation, error, allocations and GC columns; no median, p95/p99 or raw per-operation latency samples are available in this artifact.
3. Reciprocal-mean throughput is a derived estimate. A dedicated throughput benchmark should measure completed operations over a controlled interval.
4. Comparisons are valid only after checking timed-region semantics, fixture construction, lookup behavior and workload equivalence.
5. The benchmark suite measured FSM_COS source commit `207b417a7958134bbc138374a5d077b707e1faf3`; do not attribute these numbers to another source revision or to a published NuGet package.
6. Keep all validation and failure semantics intact. Performance work must not remove correctness or security checks to improve a score.
